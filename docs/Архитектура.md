# Архитектурное видение

Лисаковск Hub создаётся как платформа цифровых экосистем малых городов.

Главная цель платформы:

Создать цифровую инфраструктуру города,

объединяющую жителей,

бизнес,

сообщества

и локальные сервисы

в единой экосистеме.

---

# География платформы

Первым Hub является:

Лисаковск Hub

В дальнейшем:

* Рудный Hub
* Костанай Hub
* другие города

Каждый город представляет собой отдельную экосистему внутри общей платформы.

---

# Основной архитектурный принцип

Все модули должны:

* усиливать друг друга;
* обмениваться полезными данными;
* работать внутри общей экосистемы.

При этом каждый модуль обязан сохранять независимость.

Если один модуль отключается,

остальная платформа продолжает работать.

---

# Архитектурные слои

Платформа строится по модели:

```text
Core

↓

Hub

↓

Modules
```

---

# Слой Core

Общие сущности платформы.

Является источником истины для всей экосистемы.

Содержит:

* пользователи;
* роли;
* рефералы;
* уведомления;
* платежи;
* настройки;
* экономика сообщества;
* агенты;
* лимиты.

Core не зависит от модулей.

Модули зависят от Core.

---

# Слой Hub

Hub представляет отдельный город.

Примеры:

```text
hub_id = lisakovsk

hub_id = rudny

hub_id = kostanay
```

Каждый Hub содержит:

* локальный контент;
* локальные вакансии;
* локальный бизнес;
* локальные знания;
* локальное сообщество;
* локальную аналитику.

Все города используют единое ядро платформы.

---

# Слой модулей

Модули решают отдельные задачи пользователей.

Каждый модуль является самостоятельным продуктом внутри экосистемы.

---

# Текущие модули

Активные:

* Работа

Проектируемые:

* Артель
* Каталог организаций
* Архив города
* Афиша
* Коллективный разум
* Спроси город
* Недвижимость
* Валидатор стартапов
* Торговая площадка
* Перевозки

---

# Принцип независимости модулей

Каждый модуль:

* имеет собственную бизнес-логику;
* имеет собственные таблицы;
* может развиваться отдельно;
* может временно отключаться без остановки платформы.

Пример:

```text
Работа

├ job_seekers
├ job_vacancies
└ job_responses


Архив

├ archive_documents
├ archive_photos
└ archive_tags
```

Отказ одного модуля не должен влиять на остальные.

# Единая идентичность пользователя

Пользователь существует один раз.

Основной идентификатор:

```text
user_id
```

Один пользователь может одновременно быть:

* жителем;
* соискателем;
* работодателем;
* предпринимателем;
* организатором;
* владельцем бизнеса.

Система не должна создавать дублирующиеся сущности пользователя.

---

# Слой сообщества

Отдельный слой экосистемы.

Назначение:

* удержание пользователей;
* формирование привычки пользоваться платформой;
* накопление знаний;
* развитие городской идентичности.

Содержит:

* Коллективный разум;
* Персонажей;
* Репутацию;
* Экономику сообщества;
* Базу знаний.

---

# Персонажи экосистемы

Примеры:

* Голубь
* Валера
* Русик
* Афган
* Баба Зина

Используются для:

* брендинга;
* обучения;
* маркетинга;
* вовлечения;
* юмора;
* геймификации.

# Слой аренды и масштабирования

Платформа проектируется с возможностью масштабирования на другие города.

Каждый модуль желательно оценивать на возможность:

* аренды;
* подписки;
* франшизы;
* White Label использования.

---

# Роли управления

## Супер-администратор

Управляет всей платформой.

Может:

* создавать новые Hub;
* управлять Core;
* назначать администраторов;
* изменять правила платформы.

---

## Администратор Hub

Управляет конкретным городом.

Может:

* модерировать контент;
* управлять локальными сервисами;
* работать с пользователями города;
* поддерживать локальное сообщество.

---

# Правило источника истины

Ни одно решение не считается принятым только потому, что обсуждалось в чате.

Путь принятия решения:

```text
Обсуждение

↓

Проверка

↓

ADR

↓

Документация

↓

Реализация
```

Код

и

Документация

или

Документация

и

Фактическая реализация

создаётся запись:

```text
DRIFT
```

в журнале расхождений.

Запрещено игнорировать такие ситуации.

---

# Принцип взаимной выгоды

Каждый новый модуль обязан отвечать на вопросы:

* Какую выгоду получает платформа?
* Какую выгоду получает пользователь?
* Какую выгоду получает партнёр?
* Какую пользу получает город?

Также желательно определить:

* может ли модуль сдаваться в аренду;
* как клиент сможет зарабатывать с помощью модуля;
* какие данные модуль будет собирать;
* как эти данные усилят экосистему.

---

# Главная архитектурная цель

Построить не набор Telegram-ботов.

Не сервис вакансий.

Не городской справочник.

А платформу цифровых экосистем малых городов,

в которой каждый новый модуль усиливает остальные,

накопленные данные повышают ценность системы,

а сама платформа постепенно становится цифровой операционной системой городской жизни.

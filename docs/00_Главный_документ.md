Lisakovsk Hub не является:

• ботом вакансий

• справочником

# Что считается успехом

Не идеальная архитектура.

Не красивый код.

Успехом считается:

• запуск продукта;
• первые работодатели;
• первые пользователи;
• первые платные функции;
• реальные данные использования.

# Владелец проекта

Финальным источником стратегических решений является владелец проекта.

Если:

• документация противоречит реальности;
• несколько документов противоречат друг другу;
• возникает неоднозначность;

необходимо запросить решение владельца.

Запрещено самостоятельно принимать стратегические решения.

# Принцип сохранения знаний

Любое найденное решение,

логика,

правило,

бизнес-процесс,

способ монетизации

или архитектурное решение

должны быть зафиксированы в документации.

Запрещено хранить критически важные знания только в чате.

---

# Принцип данных

Данные являются одним из главных активов платформы.

Каждый модуль обязан:

• собирать полезные данные;
• структурировать данные;
• сохранять данные;
• усиливать общую базу знаний экосистемы.

Удаление данных допускается только при наличии веской причины.

---

# Принцип взаимной выгоды

Каждый модуль обязан создавать ценность минимум для двух сторон:

1. Платформа.
2. Пользователь.

Желательно также:

3. Партнёр.
4. Сообщество города.

Перед запуском любого модуля необходимо ответить:

• Как зарабатывает платформа?
• Как зарабатывает пользователь?
• Как зарабатывает партнёр?
• Какую пользу получает город?

Если ответ отсутствует хотя бы для платформы и пользователя,

модуль требует дополнительного обоснования.

# Язык документации

Основной язык документации — русский.

Названия документов, агентов, карт и процессов должны быть понятны человеку без технической подготовки.

Английские термины допускаются только:

• для названий технологий;
• для общепринятых технических терминов;
• при необходимости указания оригинального названия в скобках.

# Дополнения к реестру ADR

---

# ADR-022. Mutual Benefit Rule

Каждый новый модуль обязан создавать ценность минимум для двух сторон:

* платформы;
* пользователя.

Желательно также:

* партнёра;
* сообщества.

Перед запуском модуля необходимо ответить:

Как зарабатывает платформа?

Как зарабатывает пользователь?

Как зарабатывает партнёр?

Какую пользу получает город?

---

# ADR-023. Data Is An Asset

Данные являются одним из главных активов платформы.

Каждый модуль обязан:

* собирать полезные данные;
* структурировать данные;
* сохранять данные;
* усиливать общую базу знаний экосистемы.

Удаление данных допускается только при наличии обоснования.

---

# ADR-024. Knowledge Must Be Documented

Любое найденное:

* решение;
* бизнес-правило;
* способ монетизации;
* архитектурное решение;
* важное наблюдение;
* найденная возможность;

должно быть зафиксировано в документации.

Критически важные знания запрещено хранить только в чатах.

---

# ADR-025. Module Rental Evaluation

Каждый новый модуль должен оцениваться на возможность:

* аренды;
* подписки;
* франшизы;
* White Label использования.

Если это невозможно,

причина должна быть зафиксирована.

---

# ADR-026. Owner Final Authority

Если возникает конфликт между:

* документами;
* архитектурой;
* кодом;
* решениями агентов;

финальное решение принимает владелец проекта.

AI-агенты не имеют права самостоятельно принимать стратегические решения.

---

# ADR-027. Contacts Through Company

Контактные данные работодателя хранятся в карточке компании.

Вакансии используют контакты компании автоматически.

Запрещено поддерживать независимые контактные данные вакансии без отдельного обоснования.

Причина:

исключение рассинхронизации данных между компанией и вакансиями.

---

# ADR-028. AI Agents Serve MVP

До завершения MVP все AI-агенты работают на ускорение запуска продукта.

Приоритет:

1. Запуск продукта.
2. Первые пользователи.
3. Первая монетизация.
4. Реальные данные использования.

Любые инициативы, не приближающие релиз, имеют низкий приоритет.

---

# ADR-029. No Silent Drift Fixes

Если обнаружено расхождение между:

* кодом;
* документацией;
* архитектурой;
* фактической реализацией;

не допускается молчаливое исправление.

Необходимо создать запись:

DRIFT

и зафиксировать принятое решение.

---

# ADR-030. Hub Before Module

При принятии решений необходимо учитывать влияние на всю экосистему.

Решение должно приносить пользу не только текущему модулю,

но и будущим модулям платформы.

Интересы экосистемы имеют приоритет над интересами отдельного модуля.

# Правила резервного копирования

Версия:

2.0

Статус:

ACTIVE

Дата последней проверки:

2026-06-13

---

# Назначение

Обеспечить сохранность:

* пользовательских данных;
* вакансий;
* компаний;
* платежей;
* документации;
* знаний проекта;
* архитектурных решений;
* настроек инфраструктуры;
* результатов аналитики.

При любых сбоях, ошибках разработки, человеческом факторе или потере инфраструктуры.

---

# Главный принцип

Потеря данных считается критическим инцидентом.

Любая система должна проектироваться с учётом возможности восстановления.

---

# Правило 001

## Несколько независимых копий

Критически важные данные должны существовать минимум в двух независимых местах.

Рекомендуемая схема:

```text
Основное хранилище
+
Резервная копия
+
Архивная копия
```

Единственная копия данных недопустима.

---

# Правило 002

## Автоматизация прежде всего

Все регулярные резервные копии должны создаваться автоматически.

Ручное резервное копирование используется только как дополнительная мера безопасности.

---

# Правило 003

## Восстановление важнее резервного копирования

Сам факт наличия резервной копии не гарантирует безопасность.

Главный критерий:

Возможность успешного восстановления данных.

Каждая резервная копия должна периодически проходить проверку восстановления.

---

# Правило 004

## Знания также являются данными

Документация считается частью системы.

Обязательному резервному копированию подлежат:

* Источники истины;
* ADR;
* карты данных;
* карты монетизации;
* карты модулей;
* карты интеграций;
* дорожные карты;
* журналы рисков;
* журнал DRIFT;
* инструкции агентов.

---

* платежи;
* роли;

Основное хранилище:

```text

```

## Код и инфраструктура

Содержит:

* исходный код;

```text

```

после каждого значимого изменения.

* исследования;
* бизнес-гипотезы.

Хранилища:

```text
GitHub

Локальный архив
```

Периодичность:

еженедельно.

---

# Уровень 4

## Архив проекта

Содержит:

* старые версии;
* завершённые этапы;
* исторические данные;
* резервные снимки проекта.

Периодичность:

ежемесячно.

---

# Правило трёх копий

Каждый критически важный актив должен иметь минимум три экземпляра:

```text
Основная копия

↓

Резервная копия

↓

Архивная копия
```

---

# Контроль резервного копирования

Необходимо контролировать:

* успешность создания копии;
* размер копии;
* целостность данных;
* возможность восстановления;
* актуальность копии.

---

# Проверка восстановления

Не реже одного раза в месяц необходимо проверять возможность восстановления:

* базы данных;
* документации;
* исходного кода;
* настроек системы.

Копия считается рабочей только после успешного теста восстановления.

---

# Контроль удаления

Перед удалением любого важного объекта необходимо проверить:

1. Существует ли резервная копия.
2. Существует ли архивная копия.
3. Назначен ли владелец данных.
4. Получено ли разрешение на удаление.

Если хотя бы один пункт не выполнен —

удаление запрещено.

* документация;
* накопленный опыт;

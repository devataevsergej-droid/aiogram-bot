Этот документ предназначен для быстрого погружения в контекст проекта.

объяснить любому агенту, разработчику, аналитику или подрядчику:

* какие решения уже приняты.

---

# Что такое Лисаковск Hub

Лисаковск Hub — это цифровая экосистема небольшого города внутри Telegram.

Проект не является отдельным ботом.

Проект не является обычным каталогом.

Проект не является просто сервисом вакансий.

Лисаковск Hub создаётся как цифровая операционная система городской жизни.

---

# Текущая стадия проекта

Статус:

PRE-LAUNCH MVP

Основной активный модуль:

Работа.

Цель текущего этапа:

Запустить первый рабочий модуль.

Получить первых пользователей.

Получить первые данные.

Получить первую монетизацию.

---

# Текущий приоритет

Главный приоритет проекта:

Модуль «Работа».

До завершения MVP запрещается отвлекать значительные ресурсы на разработку крупных новых подсистем.

Новые идеи допускаются только в формате документации, проектирования и накопления знаний.

---

# Почему проект начинается с работы

Рынок труда позволяет одновременно получать:

* пользователей;
* работодателей;
* данные;
* аналитику;
* первые деньги.

Модуль «Работа» является входной точкой в экосистему.

# Главный актив платформы

Главный актив Лисаковск Hub:

* данные;
* знания;
* документация;
* сообщество;
* доверие пользователей.

Не код.

Не интерфейсы.

Не отдельные боты.

---

# Архитектурный подход

Платформа строится по модели:

Core

↓

Hub

↓

Modules

Core содержит общие сущности.

Hub координирует работу экосистемы.

Modules решают конкретные задачи пользователей.

---

# Текущие модули

Активный:

* Работа

Запланированные:

* Артель
* Каталог организаций
* Архив города
* Коллективный разум
* Спроси город
* Афиша
* Торговая площадка
* Перевозки
* Валидатор стартапов

Список может расширяться.

---

# Принцип модулей

Каждый новый модуль обязан:

* усиливать данные платформы;
* усиливать пользователей платформы;
* усиливать монетизацию платформы;
* усиливать другие модули экосистемы.

Изолированные модули не являются приоритетом.

---

# Принцип взаимной выгоды

Каждый модуль обязан создавать ценность минимум для двух сторон:

1. Для платформы.
2. Для пользователя.

Желательно также:

3. Для партнёров.
4. Для городского сообщества.

Перед запуском нового модуля необходимо ответить:

* Как зарабатывает платформа?
* Как зарабатывает пользователь?
* Какую пользу получает город?

---

# Монетизация

Текущие направления:

* публикация вакансий;
* бусты вакансий;
* закрепление вакансий;
* срочные вакансии;
* подписка работодателя;
* аналитика рынка труда.

Будущие направления:

* аренда модулей;
* подписка на модули;
* White Label решения;
* продажа аналитики;
* валидатор стартапов;
* лидогенерация;
* нативное продвижение.

---

# Данные

Каждый модуль обязан собирать данные.

Каждый модуль обязан структурировать данные.

Каждый модуль обязан усиливать общую базу знаний платформы.

Удаление данных без причины не приветствуется.

# Что считается успехом

Не идеальная архитектура.

Не красивый код.

Успехом считается:

* запуск продукта;
* первые пользователи;
* первые работодатели;
* первая монетизация;
* первые реальные данные использования.

# Долгосрочная цель

Построить платформу городских экосистем.

Где новые продукты создаются не с нуля,

а собираются из существующих модулей,

данных,

знаний,

процессов

и накопленного опыта.

Лисаковск является первой площадкой для построения и проверки этой модели.

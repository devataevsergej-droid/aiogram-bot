# Журнал_DRIFT

Версия: 1.0

Статус: ACTIVE

Проект: Lisakovsk Hub

---

# Назначение

Данный журнал используется для фиксации расхождений между:

* документацией;
* кодом;
* архитектурой;
* фактической реализацией;
* принятыми решениями ADR.

---

# Что считается DRIFT

DRIFT возникает если:

Документация говорит одно,

а код работает иначе.

Или:

ADR требует одно,

а реализация отличается.

Или:

существует несколько противоречащих друг другу источников информации.

---

# Главное правило

Запрещено молча исправлять расхождения.

Сначала необходимо зафиксировать DRIFT.

После этого принимается решение:

* исправить код;
* исправить документацию;
* создать новый ADR;
* оставить как есть с обоснованием.

---

# Статусы DRIFT

## OPEN

Расхождение найдено.

Решение ещё не принято.

---

## REVIEW

Проводится анализ.

---

## APPROVED

Принято решение по исправлению.

---

## FIXED

Расхождение устранено.

---

## REJECTED

Расхождение признано неактуальным.

---

# Пример

## DRIFT-001

Дата:

2026-06-15

Источник:

Состояние_продукта.md

Тип:

Структура данных

Описание:

Редактор вакансии использует поле:

salary

Тогда как вакансия хранится через:

salary_min

salary_max

Текущее состояние:

Редактирование работает по старой структуре.

Ожидаемое состояние:

Редактор использует salary_min и salary_max.

Влияние:

Высокое.

Может привести к ошибкам редактирования.

Решение:

Исправить редактор вакансии.

Статус:

OPEN

Ответственный:

Разработчик

---

# Правило закрытия DRIFT

Запись может быть переведена в статус FIXED только после проверки:

* кода;
* документации;
* связанных ADR.

---

# Связь с ADR

Если исправление меняет архитектурное решение,

необходимо:

1. Создать новый ADR.
2. Обновить документацию.
3. Закрыть DRIFT.

---

# Цель журнала

Сделать развитие платформы прозрачным.

Сохранять историю изменений.

Не допускать расхождения между:

* знаниями;
* документацией;
* архитектурой;
* кодом.
